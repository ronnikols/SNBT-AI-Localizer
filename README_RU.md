</p> # SNBT AI Localizer

[English](README.md) | Русский

Переводчик файлов квестов FTB для Minecraft (`.snbt` и нового формата FTB Quests 26.x `.json5`) с поддержкой локальных и облачных моделей, четырёхвкладочным интерфейсом и интеллектуальной системой кэширования на основе SQLite.

## Установка

### Рекомендуемые способы
| Платформа | Команда |
|-----------|---------|
| Arch Linux AUR | `yay -S snbt-tr` |
| Flatpak | `flatpak install org.mineai.snbt-tr` |
| pipx | `pipx install snbt-tr` |
| PyPI | `pip install snbt-tr` |

### Ручная установка
```bash
git clone https://github.com/ronnikols/SNBT-AI-Localizer.git
cd SNBT-AI-Localizer
pip install -r requirements.txt
```

## Использование

### Способы запуска
- `snbt-tr` — запускает интерактивный мастер настройки CLI
- `snbt-tr --gui` — запускает графический интерфейс PyQt6 с двумя вкладками
- `snbt-tr [опции]` — пакетная обработка без диалогов

### Примеры
```bash
snbt-tr --list-models -p groq
snbt-tr -d /путь/к/квестам -p groq -k ВАШ_API_КЛЮЧ
snbt-tr --mix -d /путь/к/квестам
snbt-tr --clear-cache
snbt-tr --fastdir
```

## Возможности

### Четырёхвкладочный интерфейс GUI
- **Вкладка Workspace**: Основной интерфейс перевода с выбором провайдера/модели, управлением пулом API-ключей (до 10 ключей), вводом пользовательского контекста, выпадающим списком целевого языка, панелью управления пакетной обработкой (Start/Pause/Stop) и выводом лога в реальном времени
- **Вкладка Translation Memory**: Визуальный менеджер кэша с:
  - Поиском по оригинальному и переведённому тексту в реальном времени с задержкой 300мс
  - Фильтром по модпаку через выпадающий список для изоляции переводов по модпакам
  - Фильтром по целевому языку, синхронизированным с вкладкой Workspace
  - 4-колоночной таблицей QTableWidget (Оригинал, Перевод, Модпак, Добавлено) с автоматической подгонкой ширины колонок
  - Редактированием переводов прямо в таблице
  - Массовыми операциями: Загрузить ещё (пагинация), Удалить выбранное, Сохранить изменения, Очистить кэш
  - **Кнопкой Auto-Fix**: двухстадийный хилер кэша — сначала чинит сломанный технический синтаксис (`% s` → `%s`, `__TAG _12__` → `__TAG_12__`, markdown-ссылки), затем сканирует весь кэш на мусорные переводы (≥90% слов не на целевом языке, иероглифы-протечки, слова-гибриды двух алфавитов типа «Лимитite») и переспрашивает их у **активной модели**, проверяя каждый ответ LLM перед записью
- **Вкладка Settings**: Управление настройками провайдеров, моделей, API-ключей и параметров приложения
- **Вкладка Credits**: Отображает информацию о проекте и благодарности

### Асинхронная обработка
- Неблокирующий ввод/вывод на основе `asyncio` и `httpx.AsyncClient`
- Настраиваемая параллельность (1-10 потоков)
- Адаптивное разбиение на чанки:
  - 5 элементов для Ollama (локальный инференс)
  - Настраиваемый размер пакета (по умолчанию: 50) для облачных провайдеров
- Автоматические задержки между чанками для предотвращения ограничений по частоте запросов

### Отказоустойчивость
- Round-Robin пул ключей с автоматической балансировкой нагрузки
- Невалидные ключи (HTTP 401/403) удаляются из пула навсегда
- Ключи с ограничением по частоте (HTTP 429) блокируются с экспоненциальным откатом (0.2с → 64с)
- Резервный режим: перевод по одному элементу при падении пачки
- Режим Mixed Provider: автоопределение провайдера по префиксу ключа и использование сохранённых настроек
- Binary split fallback: рекурсивное разбиение чанков при ошибках парсинга

### Интеллектуальная система кэширования
- Кэш на основе SQLite с режимом WAL для параллельного доступа
- Отдельные таблицы для каждого языка (`cache_{lang_code}`) для предотвращения перемешивания данных
- Изоляция по модпакам: переводы можно фильтровать и управлять по модпакам
- Потокобезопасные операции с блокировкой
- Сохранение между чанками в реальном времени
- Защитная санитизация: автоматическая очистка вложенных словарей в SNBT и защита от некорректного JSON в ответах
- Защита от отравления кэша: identity-записи (перевод = оригинал) никогда не считаются попаданием в кэш
- Попадания в кэш логируются («Cache: N string(s) from cache»); политика `overwrite` полностью обходит кэш — каждая строка переводится заново

### Поддержка FTB Quests 26.x (.json5)
- Автоматическое определение нового формата `lang/en_us/*.json5` (FTB Quests 26.x / MC 26.x)
- Построчная работа: перевод каждого файла в `lang/ru_ru/<файл>.json5`, с бэкапами `.json5.bak`
- Списочные значения (описания квестов) разворачиваются как `key[idx]` и собираются обратно после перевода
- Стратегии complement и overwrite, как и в SNBT

### 🛡️ Pluralization Guard
**Предотвращает избыточные API-запросы для похожих строк с порогом схожести 90%**

Pluralization Guard — это продвинутая система нечёткого сопоставления, которая автоматически обнаруживает и повторно использует переводы для похожих фраз, предотвращая дублирование API-запросов и экономя средства. Работает следующим образом:

1. **Проверка точного совпадения**: Сначала ищет точное совпадение в кэше
2. **Фильтрация по длине**: Ищет кандидатов с длиной в пределах ±15% от исходного текста
3. **Сохранение чисел**: Гарантирует, что строки с разными числами (например, "item 1" и "item 2") **НЕ** будут сопоставлены
4. **Нечёткое сопоставление**: Использует `difflib.SequenceMatcher` с **порогом схожести 90%**
5. **Сохранение хвостов**: Сохраняет коды форматирования Minecraft в конце строк (например, "hello§a" → кэшированный "привет" + "§a")

**Примеры:**
- Вход: `"Получи 5 алмазов"` → Промах кэша
- Вход: `"Получи 6 алмазов"` → **Попадание в кэш!** (схожесть >90%, та же структура)
- Вход: `"Получи алмаз"` → Промах кэша (разное количество чисел)
- Вход: `"Получи 5 алмазов§a"` → **Попадание в кэш!** (совпадает с "Получи 5 алмазов" + сохраняет "§a")

Это предотвращает оплату за переводы:
- Вариаций множественного числа: "apple" → "apples"
- Вариаций чисел: "item 1" → "item 2" (если структура совпадает)
- Незначительных различий в форматировании: "text" → "text§a"

### Защита форматирования Minecraft
- Жёсткая защита тегов, UUID и идентификаторов сущностей через regex
- Временная замена тегов плейсхолдерами (`__TAG_N__`) во время перевода
- Сохранение всех специфичных для Minecraft кодов форматирования

### Возможности тестировщика ключей
- Проверка ключей в один клик с живым тестовым вопросом; активные ключи также показывают **баланс аккаунта**, если провайдер отдаёт его по API (RunInfra, OpenRouter, OpenCode) или подсказку с консолью (Crusoe, Groq, OpenAI, Anthropic, Cohere, Mistral, Sambanova, NVIDIA)
- Статус «Model Paused» при паузе модели на стороне провайдера (HTTP 503 `hosted_model_paused`)
- Режим Mixed Providers: автоопределение провайдера по префиксу ключа; ключи неизвестного формата явно помечаются Invalid вместо ошибочной маршрутизации
- Поддержка суффикса reasoning effort: синтаксис `model/level` (например, `zai-org/GLM-5.3-Flash/low`) с маппингом под провайдера
- Глобальная настройка temperature: спинбокс в GUI, флаг CLI `--temperature`, применяется ко всем LLM-провайдерам
